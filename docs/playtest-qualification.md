# Drinking-water playtest qualification (source inventory; not a pack pass)

**Primary shipped promise.** In a Thirst + Curios installation, players can obtain and purify ordinary water, drink it manually or equip supported filled vessels in a `water` Curios slot for automatic paid hydration, keep unfinished water credit across swaps/reconnects, and receive the correct empty vessel without duplication. Thirst depletion is owned by the native Thirst capability, not by this mod. Untagged/legacy purity 0–2 is dirty; only exact purity 3 is purified. This inventory describes source contracts and authored checks, **not successful execution of these new tests or of the full pack**.

## Named item/block acquisition ledger (source evidence, not pack proof)

- `better_drinking_water:rain_collector`: shaped-planks recipe above; native rain fill and covered negative GameTests above. Rainwater glass bottle: collector native `use` test with `minecraft:glass_bottle` and `minecraft:potion`/water result; vanilla bottle/planks acquisition in the selected pack remains unverified.
- `minecraft:water_cauldron`, `create:fluid_tank`: directly exercised in `WaterSourceGameTests`; water/source fill from ordinary play, cauldron/container crafting and permission rules are not established by those tests. `minecraft:snow_block` and `minecraft:campfire`: melt test confirms conversion but not obtainable materials or climate.
- `minecraft:potion` (water bottle), `thirst:terracotta_water_bowl`, `minecraft:water_bucket`: `WaterSurvivalGameTests.waterHasOnlyDirtyAndPurifiedQuality` covers bottle boiling; `WaterSourceGameTests.bowlsAndBucketsRemainPurifiableWithoutVesselGenerators` covers bowl/bucket boiling; `bowlAndBucketDebitOnceAndReturnTheirOwnVessel` covers consumption. The `data/thirst/recipes/` overrides encode campfire/smelting purification; they do not prove the native dirty-vessel acquisition path or fuels in a full pack.
- `tconstruct:copper_can`, `tconstruct:seared_fuel_tank`: native source debit/capability tests above, not recipe/unlock proof. `WaterSources.FLUID_ITEMS` and `BlockWaterDrinking.TANKS` enumerate additional recognized provider IDs (Tinkers, Create Diesel Generators, PneumaticCraft, AE2); allowlisting does **not** prove any such item/block is installed, obtainable or functional in the chosen pack. Same caveat for `aether:skyroot_water_bucket`, `everythingcopper:*_water_cauldron`, and the backpack empty-return path.
- Named beverages/plant drinks, if included in the qualification scope: `src/main/resources/drinks.json`, `plant_drinks.json`, `data/better_drinking_water/recipes/plant/` are the authored per-item/per-recipe catalogue; `DrinkCatalogueResourceTest`, `PlantDrinkResourceTest`, `BeverageGameTests.everyLoadedCatalogueProfileResolvesNativeItemsAndEffects` and `PlantDrinkGameTests.registeredPlantStockResolvesWithNativeRecipes` check resource and selected loaded native identities. These are **not** evidence that every named ingredient, workstation and recipe is obtainable in a new full-pack world; qualify each selected named item against its specific authored recipe/donor and selected pack registry before making an acquisition claim.

## Entry points, provider contract, and remaining gate

- `./gradlew --no-daemon test` runs JUnit/resource/diagnostic checks (including new `WaterQualityTest`); `./gradlew --no-daemon verifyFast` includes `check` and Python `scripts/test_native_*.py`; `./gradlew --no-daemon headlessGameTest` runs Forge dedicated GameTests including new 32-player fixture; `./gradlew --no-daemon verifyFull` adds strict `verifyNativeDiagnostics` audit. **Do not execute without explicit human test-run approval.** `build.gradle.kts` uses a unique native attempt directory and refuses existing worlds.
- `.github/workflows/ci.yml` on push, PR and manual dispatch invokes `./gradlew --no-daemon verifyFull stageRuntimeJar` (CI packaging included there; this authoring task did not invoke it). The source fixture requires immutable, exact provider JARs `better-compat-fixes:0.1.9` and `better-gameplay-notices:1.0.0` via `-PcompatFixesRuntimeJar=...`, `-PgameplayNoticesRuntimeJar=...` or `BC_CUSTOM_MOD_JAR_DIR` (`gradle/native-compat-providers.gradle`). `src/nativeFixture/java/.../ThirstCompatibilityGameTests.java` validates native Thirst loot codec/actual Compat recursion fix in the nonshipping fixture; it is not the whole-pack dependency graph.
- This repo has **no authored client visual/input or full-pack multiplayer/performance qualification runner**. Even a green source CI cannot certify a selected immutable modpack build, coupled server/client mods/config, fresh-world acquisition and progress, thirst depletion rates, actual network sync, 32 live players or save/reload continuity. Select exact pack candidate, preserve world snapshots, and use the pack's authorized smoke/integration and 32-player gates separately. No tests, builds, native worlds or pack checks were run while authoring this inventory.
